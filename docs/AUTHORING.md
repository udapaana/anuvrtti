# Authoring the reader

Everything a new session needs to keep writing readings without rediscovering
the constraints. Written 2026-08-16, at 246 readings / 42 of 131 rules taught.

## The one command

```bash
bun run check
```

Runs every corpus check and exits non-zero on the two that are always errors.
Run it before and after any authoring batch.

```
✓ gloss/token: 48  (baseline 48)      hard — any INCREASE fails
✓ सङ्ग्रह constraint: clean            hard — a passage may not introduce a rule
· coverage: 42/131 load-bearing rules taught
· revealed: 30% of the corpus shown by default, 42% in late attested
· teaches: median 78 chars, 0 line(s) over 240
· register: 25 term(s) used before introduction
· citations: 80 confirmed against vidyut, 39 to review
```

The soft lines are candidate lists, not failures. `register`'s 25 are mostly
terms glossed inline in the same sentence — read before rewriting.

Other commands: `bun run ledger` (coverage detail, `--full` for every rule),
`bun run verify:cites`, `bun run check:register`, `bun run build:readings`.

## Where things live

| | |
|---|---|
| authored source | `content/readings/*.yaml` — **edit these**, never the JSON |
| the plan | `content/readings/_syllabus.yaml` — conventions in its header |
| the target set | `content/readings/_rules.yaml` — load-bearing vs leaf |
| built payload | `static/data/readings.json` — generated, committed |
| quiz cells | `static/data/quiz-cells.json` — generated by vidyut, committed |

`bun run build:readings` after every edit. `bun run build:quiz` only when the
corpus gains new *words* — it is a three-pass chain (readings → cells →
readings) because the cells are derived from the corpus's own forms.

## How coverage moves

A rule counts as taught at **8 distinct readings**. A story is one reading, so
it adds one encounter per rule no matter how often the rule appears in it.
Choosing *which* rules is the whole lever.

The pattern that works, proven twice (28→35, then 36→37):

1. a **सङ्ग्रह passage** that lifts a cluster of rules to 7/8
2. a **story** that touches each of them once more, and they cross together

Pick targets from `bun run ledger`'s partial list, not by tier order.

**Before authoring against a low number, check whether it is a tagging gap.**
Four "gaps" this session turned out to be measurement errors: शप् had 118
readings containing a present verb and 2 citing it; the कारक role terms were
mapped to the wrong sūtras; 8.3.23 had 32 matching words and 3 citations. The
ledger has been wrong in the same direction repeatedly — undercounting what the
corpus already teaches.

## The chapters

`12_sangraha.yaml` holds consolidation passages. Its header carries five
authoring rules; the load-bearing one is **a सङ्ग्रह passage introduces
nothing** — every rule it cites must already appear at or below its tier. The
check enforces this and has caught violations twice, both from mechanical edits.

`09_katha.yaml` is graded narrative, `06_readings.yaml` is attested text.
Attested is 30 Ṛgveda / 8 Hitopadeśa / 3 Pañcatantra — the Ṛgveda block from
tier 280 up is a wall, and classical prose between the subhāṣitas and the hymns
is where the corpus is thinnest.

## Register — the part checks cannot catch

Four separate passes fixed prose faults, and the user caught every one of them
before the tooling did. The rules are recorded in `_syllabus.yaml`; the ones
that keep recurring:

- **`teaches` length.** Corpus median 78 characters. Lines authored later
  reached a median of 260 by narrating what a passage is *for* rather than
  naming what is in it. Now warned at 240.
- **A closing paragraph that restates the opening.** Invisible in isolation —
  the paragraph reads fine until you set it beside the one above.
- **Explaining the method, not the Sanskrit.** "That difference is what
  consolidation means", "already met", "one at a time". The reader does not
  know the corpus exists.
- **Shouty caps, `+`-chained feature lists, corpus-internal references**
  ("minimal pair with ex122" — the reader has no ids).

Say what is on the page and stop.

## Numbering

`segment` is the difficulty tier, in **tens** (10, 20, … 570), with the nine
slots between free for insertions. `id` is authoring order and nothing else —
it disagrees with pedagogical order on a third of pairs. Never renumber ids.

## Known gaps

- **39 citations to review** (`bun run verify:cites --full`). Mostly consonant
  stems vidyut cannot derive from the recorded lemma, and तद्धित rules that
  fire during stem formation. Checker limits, not corpus errors.
- **48 gloss/token mismatches** — unglossed यः/सः in ex161-165, label prefixes
  in ex038-040 and ex174-178. Real authoring gaps, listed by the build.
- **3 rules never cited**: 1.2.43, 7.3.86, 8.4.1.
- **`/review` exists but nothing links to it.** The wordBank SRS is real and
  the reader can bank words into it, but there is no surface to review them on.
  The design puts review beside the text, not on its own page.
- **The quiz gate and the recall-first token display overlap** — both make the
  reader try before seeing the gloss. The design has both; whether they should
  both stay is unsettled.
