# Writing for /ref?mode=path

The sūtra paths — ādhāraḥ, tiṅanta, subanta, kāraka, kṛdanta, taddhita, sandhi,
samāsa, prakaraṇa, prakriyā — are a guided walk through real sūtras, not a
paraphrase of them. This is the reference for writing or editing one: where
the files live, the exact markup the renderer understands, and the voice.

The voice section exists because the existing paths don't have one
consistently. `docs/MARKUP_SUPPORT.md` describes a markup system from an
earlier, non-SvelteKit version of this site (`assets/js/script.js`,
`RULE_EXTRACTION_SCHEMA.md` — none of that exists here) — don't use it. The
syntax below is read directly out of the current renderers
(`src/lib/content/index.ts`, `src/lib/components/CommentaryText.svelte`,
`src/lib/components/InlineMarkup.svelte`) and checked against markup already
shipping in `static/content/paths/vyakarana/*/path.md`.

## Where things live

| | |
|---|---|
| a path | `static/content/paths/vyakarana/<folder>/path.md` — one file, TOML frontmatter + a run of `##` step sections |
| the index | `static/content/paths-index.json` — generated by `bun scripts/build-path-index.ts`; run it after adding or renaming a path |
| categories | `src/lib/learning/categories.ts` — the ten `PathCategory` ids and their Sanskrit/English labels; a path's `category` field must be one of these |
| the type contract | `src/lib/learning/paths.ts` — `Track`, `PathCategory`, `LearningPath`, `LearningStep`, `QuizData`; this is what the frontmatter and step fields must satisfy |
| rendering | `src/routes/workbook/[lessonId]/+page.svelte` (a path's step-by-step page) and `src/routes/ref/+page.svelte` (`?mode=path`, the index shown above) |

There is no build step between the markdown and the browser — `loadPathIndex()`
and the per-path fetch in `src/lib/content/index.ts` read these files at
runtime. Editing `path.md` and reloading is the whole authoring loop, aside
from `paths-index.json` when frontmatter changes.

**There is no automated check for the writing itself.** `bun run check`
gates the reading corpus's annotation completeness; nothing gates a path's
prose. This doc is the gate — a reviewer reading it against the standard
below, because a linter cannot tell "meet five roots" from "here are five
roots."

## Frontmatter

```toml
+++
id = "dhatu-parichaya"
order = 1
title = "धातुपरिचयः — Introducing the Root"
titleSanskrit = "धातुपरिचयः"
label = "धातुः"
track = "grammar"
category = "foundation"
description = "What is a @term[dhātu]? How are roots listed and organized."
difficulty = "beginner"
estimatedTime = "1-2 hours"
prerequisites = ["introduction"]
+++
```

| field | value |
|---|---|
| `id` | the folder name, used in URLs — stable once published |
| `order` | position within the category, on `/ref?mode=path`'s list and prev/next |
| `label` | the short Sanskrit shown in the category sheet and the header on `/ref?mode=path` (`"chapter N of M"` sits above it) — one or two words |
| `track` | `"grammar"` for these; `"reading"` is a separate track |
| `category` | one of the ten ids in `categories.ts` — this is what the category sheet groups by |
| `description` | one or two sentences; `@term[...]` works here (rendered via `InlineMarkup`) |
| `difficulty` | `"beginner" \| "intermediate" \| "advanced"` |
| `prerequisites` | array of other paths' `id`s |

## Steps

```markdown
## 1.3.1 - भूवादयो धातवः

**Key Terms:** dhātu, bhvādi

Commentary goes here. @sutra[1.3.1] embeds the sūtra itself — write the
teaching, not a restatement of what the embed already shows.
```

The header is `## <id> - <title>`. `<id>` is either a bare sūtra reference
(`1.3.1`) or one of the fixed keywords `concept`, `quiz`, `reading`,
`practice`, `summary`, `exercise`, `lesson` (`content/index.ts`'s
`knownTypes`) — a `concept` step is a bridge passage with no single sūtra
behind it; the numbered form is a step built around one sūtra.

Use the bare numeric form for a sūtra id. One existing step (`dhatu-parichaya`,
step 2) wrote `## @ref[1.3.1] - ...` instead — it happens to still work
because the header regex takes the token as-is, but every other path uses the
plain number, and that's the one to match.

**Key Terms** is a comma-separated list, no markup, shown as clickable chips
on the step. Each one only becomes a link if it resolves in the jargon
glossary (`/ref/jargon`, backed by `src/lib/jargon.ts`) — check it exists
there (case and diacritics aside) before introducing a new one. Write real
IAST (`kartṛ`, `prakṛti`), not an ASCII stand-in (`dhAtu`) — both happen to
resolve today because the lookup strips diacritics, but the glossary's own
display form is the proper one, and relying on the stripping is an accident
of the lookup, not a documented contract.

### Markup, inline

| write | get |
|---|---|
| `@deva[रामः]` | Devanagari span, follows the reader's script toggle |
| `@[rāmaḥ]` | same, source is IAST |
| `@term[kāraka]` | clickable jargon term — must resolve in the glossary |
| `@ref[1.4.32]` | a plain link to `/ref/1.4.32` |
| `@pratyahara[aC]` | styled pratyāhāra code |

### Markup, block

These only render as embeds inside step **commentary** (`CommentaryText`) —
not in `description`, `title`, or Key Terms, which go through the plainer
`InlineMarkup` and would show the tag text literally.

| write | get |
|---|---|
| `@sutra[1.4.32]` | the full sūtra card, inline |
| `@sutra[1.4.32]{depth=standard}` | same, at a specific commentary depth (`simple` default) |
| `@sutra[1.4.32]{compact}` | condensed card |
| `@prakriya[bhU + laT + tip]` | an embedded derivation — `root + lakāra + ending`, SLP1-ish ASCII (`bhU`, not `bhū`) |
| `@prakriya[gam + laT + ta]{highlight=1.3.13}` | same, with one sūtra in the derivation highlighted |
| `@prakriya[pac + laT + tip]{collapsed}` | same, starts closed |

`@sutra[...]` and `@ref[...]` are not interchangeable: `@ref` is a citation
you'd write inline ("by @ref[1.4.32], ..."); `@sutra` is a full embed and
belongs on its own line. Using `@ref` where the reader needs to actually see
the rule sends them away from the step to get it.

### Quiz steps

```markdown
## quiz - Check Your Understanding

**Question:** In @deva[विप्राय गां ददाति] "he gives a cow to the brahmin,"
which @term[kāraka] is @deva[विप्राय]?

**Options:**

- [ ] @term[karman] — the object of the action
- [x] @term[sampradāna] — the recipient
- [ ] @term[apādāna] — the source

**Explanation:** By @ref[1.4.32], the one the agent intends to connect with
the object is @term[sampradāna]. This takes @term[caturthī], giving @deva[विप्राय].
```

Exactly one `- [x]`. Draw distractors from real alternatives the sentence
could plausibly be mistaken for, the same discipline the reader's quiz
follows — not filler options nobody would pick.

## The voice

A rule, a sound, a letter, a root does not want anything, know anything,
choose anything, or have a life. It has a definition, and the definition is
what it does. Write what it does.

**The tell:** the grammatical subject of the sentence is a rule, sound,
letter, or root, and the verb gives it a person's behavior — *meets*,
*wants*, *knows*, *chooses*, *hides*, *reveals*, *gets born*, *has a family*,
*prefers*. That sentence needs to be rewritten around the actual mechanism.

**Not the tell**, and fine as written:

- **A real sentence's agent** wanting or intending something — "rice is what
  he wants cooked" describes the agent in an example sentence, and for
  सम्प्रदान specifically, *intent* is the sūtra's own definition
  (1.4.32 कर्मणा यमभिप्रैति), not a metaphor laid on top of it.
- **A literal gloss** — "द्विष् 'he hates'" is the root's meaning, stated
  plainly, not personification.
- **An actual historical fact** — "Sanskrit and English share a common
  ancestor" is comparative linguistics, true as written.
- **Addressing the reader** — "you'll see this constantly," "as you know" —
  ordinary second person, not a metaphor.

### From the existing paths, rewritten

> Before any formal derivation, meet five roots you'll see constantly.

A root isn't a person you're introduced to.

> Here are five roots you'll see constantly:

---

> Sanskrit verbs grow from seeds called @deva[धातु] (dhātu — root).
>
> ## concept - The Seed of Every Verb

"Root" is the standard term and needs no defense. "Grow from a seed" extends
it into a botanical story the grammar doesn't have. Say what a dhātu is:

> Every Sanskrit verb is built from a @deva[धातु] (dhātu — root). Roughly
> 2000 are listed in Pāṇini's @deva[धातुपाठ].
>
> ## concept - What a Root Is

---

> Sanskrit vowels come in three "grades" or strengths. Think of it like
> gears—you shift up when forming derivatives.

The grades (guṇa, vṛddhi) are a fixed substitution relationship, not
something you "shift" through. Describe the relationship:

> Sanskrit vowels come in three grades: the base vowel, guṇa, and vṛddhi.
> Certain rules replace a vowel with its guṇa or vṛddhi grade — this table
> shows which vowel goes to which.

### A separate thing worth fixing alongside it

`introduction/path.md` opens "Welcome to Pāṇinian Grammar" and moves through
"Let's begin with something concrete" — a warmer, more conversational
register than the rest of the site (`AUTHORING.md`, the reading corpus, the
UI copy) ever uses. That's not anthropomorphization, and it's a separate call
than the one above — flagging it here because fixing the metaphors without
touching the register would leave the paths sounding like two different
documents. If you're rewriting a path's opening for the metaphor problem,
match the direct, second-person-but-not-chatty register the rest of the
paths already use elsewhere in the same files (e.g. dhātu-parichaya's "This
path shows you: ...").

## What's actually in ādhāraḥ right now

Two paths, 30 steps between them:

| id | steps | covers |
|---|---|---|
| `introduction` | 22 | vowel grades, pratyāhāra, it-saṃjñā, pada, pratyaya |
| `dhatu-parichaya` | 8 | what a dhātu is, the ten gaṇas, five common roots, the shape of a derivation |

Fleshing this out means both: new foundation-level paths (nothing here yet
covers, for instance, the māheśvara sūtras themselves as an object of study,
or a first pass at saṃjñā rules generally before kāraka needs them), and a
pass over these two for the metaphor and register issues above — dhātu-
parichaya has the worst instances of the first problem and is the one most
worth revising before adding to the category next to it.
